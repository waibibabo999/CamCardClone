## 四、采集过程中发现的关键差异（写报告要用）

| # | 发现 | 对本项目的影响 |
|---|---|---|
| 1 | 参考 App **没有独立的"扫描入口"页**，底部中央相机按钮直接进入相机，相册入口在相机页内 | `spec/requirements.md` 的"扫描入口"页是自建设计，属合理简化，需在报告中声明 |
| 2 | 参考 App **会补全与规范化信息**：地址前自动加"中国"、生成拼音排序名（如 `ShangHaiYuanJingKeJi`）、自动匹配公司库、AI 高精度识别、企业工商情报 | 作业明确禁止"补全名片上不存在的信息"。本项目**不做**这些，属作业授权的偏差 |
| 3 | 参考 App **支持多个电话与多个邮箱**，结果页有两行"工作邮箱" | 直接证明 `design/data-model.md` 的单 `email` 字段不够用，D5 必须决议 |
| 4 | 删除是"云端回收站 30 天可恢复"的语义 | 本地 App 只能硬删除，属合理偏差 |
| 5 | 导出通讯录被标记为 **VIP 功能** | 需确认免费额度是否够用；T19 可用 VCF 导出替代 |
| 6 | 搜索同时搜本地名片与线上公开名片库 | 本项目只搜本地，属合理偏差 |
| 7 | `mp_01` 的邮箱被误识别：`luojianhua` → `iuojianhua`；`zh_02` 的邮箱 `lijingyi` → `iijlngyi`（并已保存进详情页） | **真实 OCR 错误样本**，可直接写进 OCR 错误分析章节 |
| 8 | `zh_03` 的结果里"部门:销售部"被合并进了"公司地址"字段 | 字段解析错误样本，可写进字段抽取错误分析 |
| 9 | 非名片图像会产生大量垃圾字段（`18_ocr_garbage_input.png`） | 说明 OCR 需要"是否为名片"的判断，可作为异常路径设计依据 |
| 10 | 测试名片确实是通过拍摄笔记本屏幕采集的（`08_scan_detect_frame.png`、`12_detect_manual_*.png` 可见屏幕边框） | 参考 App 与本项目输入一致，对比成立；但拍摄环境（屏幕反光）需在报告中说明 |
| 11 | 参考 App **没有"无法识别"这条路径**，一切输入都会产出字段 | 作业 T20 明确要求"无法识别"异常路径。本项目按作业要求实现"检测失败 → 手动录入"，并声明这是作业要求带来的偏差 |
| 12 | 详情页可查看原图，且**原图与处理后的图是两张可切换的图**（轮播两点；`28_card_image_viewer.png` 有「使用原图」按钮） | 直接印证 `BusinessCard` 的 `originalImageFileName` / `processedImageFileName` 双图设计是必要的 |
| 13 | 原图查看页支持保存后再次「重拍 / 旋转 / 删除 / 手动切边」 | 参考 App 允许保存后再校正；本项目只在识别流程内提供校正，属合理简化，需写入报告 |
